## 1. 总流程与共同原则

销售新建项目 → 按类型建立设计任务 → 设计交接并建立/关联生产任务 → 生产或生产批次 → 销售出货申请 → 飞书原生审批 → 出货 → 安装（仅需安装的定制）→ 验收/交付 → 售后工单（独立服务）。异常与外购采购是并行支线；项目阶段和风险状态分别保存。

| 类型 | 设计路径 | 生产路径 | 分批/安装 |
| --- | --- | --- | --- |
| DZ 定制 | 下述完整 9 个人人工节点 + 系统自动“设计完成” | 下述完整生产路径 | 可分批；按项目是否需要安装决定唯一安装档案 |
| BS 板式 | 设计师分配 → 复尺确认 → 客户最终确认 → 开始拆单 → 转接生产 → 自动设计完成 | 木工后跳过打磨、油漆和外购，后接组装打包/出货 | 不分批、不安装 |
| WJ 外接 | 客户最终确认 → 系统转接生产/设计完成 | 完整生产路径 | 不分批、不安装；只能外接负责人或管理层建项 |
| CP 成品 | 负责销售做客户最终确认 → 自动设计完成 | 组装打包 → 出货申请 → 准备出货 | 不分批、不安装；建项同时产生关联生产任务 |
| QC 清仓 | 同 CP | 同 CP | 不分批、不安装 |

五类项目**同名节点使用同一字段名称、类型、选项和校验定义**，不同路径只显示适用节点；不为跳过节点填写假数据。“四类项目”的旧标题应按五类理解。系统自动节点不让员工手动填报。项目编号自动生成；关联、任务、批次和审批要防重复创建。

### 1.1 项目总表

新建项目必填：项目类型（DZ/BS/CP/WJ/QC）、客户姓名、联系电话、精确地址、来源渠道（线上客资/客户介绍/自然到店/合作商家/其他渠道）、客户类型（B端/C端）。备注选填；是否样板间保留原适用选项。手机号与座机的具体校验范围尚需明确，不强行限制为 11 位。销售仅管自己项目，设计师按分配项目，生产/安装按其任务与岗位，管理员全局；查看与编辑分别核验。

项目录入支持语音输入辅助，但识别文本必须由操作者核对后才写入字段；不能因为一句语音自动推进节点。

### 1.2 手机与电脑

手机进入工作台，底部“待办、项目、申请、我的”；电脑用左侧导航。当前事项优先，表单可保存草稿与提交完成分开；断网文字草稿按账号隔离，联网后由用户手动提交。日期用可操作日历选择；生产和生产批次业务时间**不默认今天**。支持拍照或文件上传，失败保留输入，提交需防重复。

手机页面减少横向晃动及误触缩放：默认限制网页手势缩放，管理员可按**具体员工**开启“允许手机手势放大页面”；不能承诺限制浏览器/系统级无障碍放大。该选项只控制界面行为，不代替服务端权限。手机与电脑均不得整页横向滚动；重要按钮需便于触控。

试用版仅用本地虚构账号；正式上线统一使用飞书员工身份登录，不能沿用统一初始密码。正式站点使用 HTTPS，原系统 8199、隔离演示 8299 与本次 NocoBase POC 13082 是三个不同入口，互不表示已同步上线。

## 3. 主生产、外购与生产批次

主生产人工业务节点为：下单备料 → 材料到场 → 生产开料 → 木工制作 → 原件打磨 → 油漆喷刷 → 组装打包；外购入库**从原件打磨起独立并行**，结束前与组装打包共同核对。出货申请、准备出货由出货审批/发货动作驱动，不能在生产看板绕开审批直接推进。旧线性列表可用于查看顺序，但外购应标“并行/待处理/已完成”，不能显示成“跳过”。

| --- | --- | --- | --- |
| 下单备料 | 木工生产负责人；被转接生产选中的演示外接负责人可与演示木工主管共同处理本项目；管理员兜底 | 材料下单状态（待开单/已下单）、材料下单时间必填；生产负责人**直接显示转接生产的完整多选名单**，不再另选、不只显示第一人；材料单原件、设计反馈、备注可选；拆单图纸只读引用上游文件。 | 待开单可保存，已下单后再完成节点。 |

**所有主生产和生产批次的业务日期初始留空**，负责人自己选填；不因打开表单自动写今天。设计、出货、安装日期默认方式不属于本次生产日期纠正范围。生产是否异常可保留原 Word 的“否/是”选项，但它不能替代逐条异常账本，也不要把“是否分批次制作”的空白规则误套成异常状态。

油漆喷刷节点另有语音输入并识别对应字段的需求，识别后须让操作者核对确认；木工制作未来可继续细分子节点，但本轮不擅自增加新的推进关卡。

### 3.1 分批与出货

- 选择分批后，主生产不再替单一批次推进，初始生成第 1、第 2 批；后续按最大批号 +1 创建新批。每批填写“本批生产内容”，按开料/木工/打磨 → 油漆/包装 → 本批次出货申请走。有效/作废状态和作废原因留历史；已发货批次不能通过作废抹掉事实。
- **一个生产批次整批发货**，不在此版做同批按数量拆发。一张实际出货审批可以覆盖多个已准备好的有效生产批次；一次实际出货只对应一张审批。多批合并出货的当前隔离版尚未完整实现，不能把模型规则视作已验收。
- 进度按有效批次计算：生产完成有效批次数 / 总有效批次数；出货覆盖进度为已被完成出货记录覆盖的有效批次数 / 总有效批次数，**不是出货次数 / 批次数**。是否“本项目批次已建齐”须显式核对，防止把目前建的批次发完误判为合同齐货；由谁确认与重开仍待指定。
- 已发货批次如需退回生产，只允许管理员带原因补正历史资料；实际发货时间、状态、原审批不可撤销或覆盖。未发货批次补正后，下游待处理审批/派工要按依赖暂停、重新核对，完成审批的历史记录保留。

## 4. 出货审批、安装与售后

出货审批状态：待发起草稿 → 管理层审批（财务确认尾款、演示审批主管确认发货条件）→ 待填出货信息 → 待出货 → 已完成；驳回与终止另走分支。财务与演示审批主管的真实串行/会签顺序以隔离环境核对的飞书审批定义为准。正式环境审批在飞书，系统负责发起、回调和状态展示；无凭据时的模拟实例号只限演示，不得当成正式审批成功。已存在可带出的资料不要求销售重复填写；本次出货收货信息保留快照，项目编号关联不可随意改成另一个项目编号。约定发货时间、是否分派安装、客户确认状态按 Word 填写；实际发货由发货负责人记录并通知。

出货申请页面必须展示**可修改的客户姓名、电话、详细地址与出货内容**，销售确认最终收货快照后再逐项勾选四项核对，不得只给四个勾选框而看不到详细值；本次申请修改不反向覆盖项目主档。按原 Word，“是否分派安装”默认否，仍由销售在出货信息节点核对确认；它与“是否分批次制作必须留空待选”是不同字段、不同决定。

**定制多批次安装已确认：**仅在项目级确认需要安装且首批货物**真实发货后**，创建一条唯一的安装跟踪档案。后续批次不再重复建安装任务；可提前看安装资料、核对地址和预计安排。**只有批次确认建齐、所有有效批次生产完成且被已完成出货覆盖、所需外购满足、没有阻止派工的未关闭异常，才允许正式派工。** 安装不拆成多批次。Word 中“全部发完后才创建/激活”的旧句由本条取代；“创建档案”与“允许派工”是两个不同事件。如首批发货后安装意向才由否改是，补建唯一档案而不等下一次出货。单批次同样不能在货未实际发出时完成交付。

| 安装节点 | 操作人 | 主要字段与门禁 |
| --- | --- | --- |
| 安装确认 | 安装负责人 | 安装地址、确认安装时间必填，备注选填；可跟踪资料，正式派工受齐货门禁。 |

## 5. 节点查看、退回、权限和异常

### 5.1 查看与退回

1. 能看见某项目的人，可打开该项目设计、生产、安装的**任意适用节点详情**，查看已保存信息、历史资料及附件；未到达节点显示字段但不制造值。最终报价表按第 2 节单独过滤，初量尺报价表照常可见。附件下载和历史快照必须在服务端执行同样的报价权限。
2. 正常点击节点是**查看**，不出现退回原因框；节点详情里另有“退回此节点”按钮，点击后再填写原因并确认。删除“退回指定节点”的自由输入旧入口。可以从步骤条直接点历史节点进入详情，不要求先进入编辑页。
3. 普通员工只能退回**自己有权编辑**且已到达/完成过的适用节点，并受本项目归属及指定操作人限制。若后续已有别的岗位完成交接，例如销售完成“初稿客户确认”，设计师不得自行退回到该销售交接之前；由管理员协调。能查看并不等于能编辑或退回。
4. 管理员可在已走过的设计、主生产、安装节点之间**任意次数**退回，不受“只能退一次”的旧建议限制；每次都要原因、操作人、时间、原节点、目标节点和旧值记录。不能跳到未来或不适用节点。完成/终止项目的单独重开条件尚未确认，不从“任意节点退回”推导已终止可无条件重开。
5. 退回不清空字段或附件；重新打开目标节点回显原值，替换文件也保留历史版本。相关下游变“待重新确认/暂停”，重新完成时复用关联任务与批次、检查幂等，不重复创建通知/审批。已发生的发货、审批、收款和安装事实保留。审批回调若迟到或重复，不能让已暂停任务擅自放行。

### 5.2 岗位与数据权限

销售：本人项目设计确认/出货申请/客户确认；设计师：分配给自己的项目和指定拆单节点；木工：本人负责的木工节点；油漆：本人负责的油漆与包装节点；五金采购：外购；发货：实际发货；安装：对应安装节点；财务与演示审批主管：原生审批相应环节；管理员：全局查看和带原因纠错。演示外接负责人除本人创建的 WJ 项目，还应看到并共同编辑**转接生产把他列为负责人**的生产任务，不能因其外接组身份而丢掉共同负责权限。“下单备料”的生产负责人只读继承转接生产的多人列表。权限判断在服务端核对记录归属、指定人员和当前状态，前端按钮仅提示。

原 Word 的权限模型以**权限组/部门**配置页面、数据范围和岗位能力标签；员工入组继承组权限，岗位能力可叠加，业务判断不依赖组名字符串。原有五档数据范围为：全部数据、仅自己创建、仅分配给自己、全部生产项目、安装与售后项目。原 Word 角色摘要：销售仅本人项目；设计师仅分配项目；木工以定制和分配的板式生产为主；油漆组可看生产项目；五金采购全局查看且处理采购；发货组集中准备出货；外接组原为自建项目；安装组看安装/售后；财务全局查看但仅做审批；售后客服可叠加其他能力。**后续明确变更优先：**演示外接负责人被分配生产的项目也可看/共编，木工演示木工主管不可据组能力改油漆及其后续节点；项目可见人可只读看适用节点，但最终报价仍受独立附件权限。权限组合的具体行级结果必须以真实员工和隔离账号服务端请求实测。

原 Word 页面范围包括项目总览、项目列表、设计任务、生产看板、出货审批、安装管理、售后服务、数据报表、员工管理和表单字段设置。数据报表展示项目漏斗、阶段分布、异常趋势、交付准时率、岗位工作量；原 Word 允许管理层及五金采购查看，但报表数据仍须按授权范围过滤，最终报价不因报表权限泄露。

### 5.3 异常与阶段

异常逐条追加，保留来源、登记人/时间、描述、处理意见、是否阻塞、关闭人与时间，不允许以一个“否”覆盖其他未关闭问题。来源先支持 production/install/batch，数据结构允许扩充。新异常默认阻塞；生产/安装负责人可报备与提处理意见，**仅管理层可改为非阻塞**。项目阶段保持原位，风险状态独立显示；只有所有相关异常都关闭后才可清除风险提示。阶段待确认的历史项目计入项目总数，不计正式阶段分布，单列提醒。是否阻止某个节点推进按该异常的阻塞标记和影响范围判定，不让普通问题无差别卡死全部流程。
