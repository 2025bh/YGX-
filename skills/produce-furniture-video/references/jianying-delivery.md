# 剪映可编辑交付与移机

## 不依赖作者电脑

本Skill携带规则、配置/镜头模板和计划校验器，不包含营销视频后端、FFmpeg二进制、剪映、音色模型、参考视频或原片。接收方须有自己的授权素材与剪映；使用现有兼容导出器或原生UI完成剪辑。不会生成草稿的环境先给镜头计划与明确手动操作，不伪装自动完成。

## 交付关卡

1. 读取接收方剪映配置实际草稿目录、版本和运行状态，核对现有可见草稿实际路径、空间和写权限。自定义草稿目录与首页索引可能不在同一盘，不能仅凭一个配置字符串猜索引。
2. 独立目录生成草稿，每版唯一ID；画面、独立文字、旁白、音乐、音效分轨。核对源区间、总帧、目标比例、全部文本及所用文件路径。完整解码审片MP4。
3. 工程包收齐所有用到的原片/派生片及音频、图片等依赖；用相对包路径与SHA256清单。导入时重定位到接收方素材位置，不保留发送方绝对路径。保留原片便于继续改，不因去头尾规则物理裁坏原片。
4. 已验证兼容的原生UI导入可以在应用内完成。若导出器须外部登记首页索引，先备齐包、目标位置、真实索引、唯一ID、校验和回读方法，再一次性请用户保存并完全退出，检测相关进程确实退出后才写索引。运行中不外部修改索引、不强杀、不替用户关闭未保存编辑。
5. 先备份目标索引/元数据，再只增补该任务唯一条目；旧条目和ID保留。重复导入回读原结果，不覆盖用户精修工程；路径、同ID或索引存在歧义停止，不向多个猜测目录复制。
6. 回读草稿目录、所有素材路径、唯一ID、旧条目保留后才请求重开。原生首页截图或用户明确确认“看到了”才说首页可见；应用重开后再回读索引。
7. 打开工程完整播放。在工作副本修改一条文字和样式确认其他不变，检查音轨可编辑；保存、返回首页、重开检查保留，再做导出。不要为了测试随意改用户精修稿。

## 状态和失败恢复

| 状态 | 必要证据 |
| --- | --- |
| 文件已生成 | 文件存在、可解码、路径和时间线校验 |
| 工程包已生成 | 依赖完整、包哈希通过 |
| 已登记 | 实际目录和索引回读、唯一ID及旧条目保留 |
| 首页可见/已打开 | 原生界面证据或用户明确确认 |
| 编辑保存重开通过 | 工作副本隔离编辑及重开证据 |
| 内容认可 | 用户审片认可，不推断 |
| 已发布 | 实际发布证据及对应授权 |

超时先查真实结果，部分成功只补缺失关卡，不能重新生成所有产物。用户“看不到”说明交付尚不满足，检查目录、索引、进程、筛选排序及实际报错，再给一个具体下一动作；不要无新增证据反复要求退出重开。工具截图失败就报告准确错误，不使用旧坐标盲点。保留失败版本及备份，未经审核不清理。禁止用registered返回、静态JSON或FFmpeg预览替代原生验收。
