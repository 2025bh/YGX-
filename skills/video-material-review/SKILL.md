# 本地视频筛选与双端裁切

把逐个打开、观看、裁剪、改名和分类变成批量扫描、分批审核、逐条定点和统一导出。默认质量优先、宁缺毋滥。规则适用于本地工具或Agent，不依赖作者电脑路径、账号或数据库。

## 环境与边界

- 开始时确定输入目录、输出目录、用途、命名日期和本机工具。已有明确配置就复用，不要求用户重复填写。
- 检查FFmpeg（处理视频）、FFprobe（读取元数据）是否可用；缺失时说明限制，安装另获授权。不自动安装第三方Skill或付费服务。
- 有素材台时，网页和Agent共用它的业务接口、数据库及队列；先读当前版本的接口说明，不臆造命令。没有素材台也可用本地FFmpeg及结构化审核记录执行。
- 本Skill交付的是筛选操作规范，不包含素材台软件、自动视觉识别模型、音频转写服务或FFmpeg安装包。安装Skill不等于这些能力已经可用。
- 不擅自联网上传素材、调用外部AI API或发布内容。默认本地处理；模型查看画面仍会消耗额度。

## 必执行顺序

### 1. 横竖屏分开，竖屏优先

- 主要使用竖屏素材。先按原片实际显示方向分组，再筛选、裁剪和导出；横屏不能混入竖屏精选。
- 使用旋转元数据及实际显示宽高判断，必要时结合像素宽高比和画面核对；不能只看编码宽高。显示宽大于高是横版，小于高是竖版；正方形或方向无法确定的单独待复核，不强行归类。
- **禁止把横屏放大、裁掉左右、拉伸或转动内容，当成竖屏使用。** 横屏即使清晰稳定，也只能归入横版素材；不因竖屏优先就判横屏不可用。
- 保持原始画幅和正常观看方向。竖屏不等于一律9:16，不擅自将其他竖屏比例强制裁成9:16。
- 横版视频的大文件夹名称必须包含“横版”，例如`项目名-横版素材/批次/日期/分类`；竖版单独放在`项目名-竖版素材/批次/日期/分类`。名称已有明确标记可沿用；混合输入必须分别导出，不仅在备注里区分。
- 从元数据恢复正确观看方向不等于把真实横屏改成竖屏。导出前校验每条方向与目标大文件夹一致；如果用户要求用横屏替代竖屏，说明与本规则冲突并先确认是否修改规则，不静默执行。

### 2. 扫描原片与时长门槛

- 递归扫描MP4、MOV、MKV、AVI，扩展名大小写不敏感。跳过本次输出、已登记历史输出、缓存和临时目录；不要把导出成品重复当原片。
- 保存原路径、文件特征、原时长、分辨率、帧率、编码、音轨、旋转、可变帧率和HDR信息。损坏或无法读取时标记待处理，不伪造时长。
- **原片时长严格小于3.000秒：归为“不可用”，状态“不采用”。恰好3秒继续筛选。** 不用显示界面四舍五入后的时长做判断。
- 门槛针对原片，不针对裁剪后的成品。原片合格、裁剪后不足3秒，不因此自动淘汰。
- “不可用”是整理分类，不是删除授权。需要交付该目录时复制原片；不移动、不覆盖、不删除源文件。

### 3. 先判断可用性

先检查是否有可用片段，再分类命名。主要风险：

| 风险 | 判断规则 |
| --- | --- |
| 播放运动过快 | 在1倍原速检查，不能用播放器加速后的效果判断原片；检查有无稳定、可辨认的展示段 |
| 严重不清晰 | 主体失焦、运动拖影或细节无法用于目标用途；局部失焦不等于整片不可用 |
| 剧烈抖动 | 无意晃动、方向突变、撤机、调整机位等；正常后拉、平移、有意旋转不能一律判为抖动 |
| 严重曝光 | 主体关键细节过曝或欠曝不可用；白墙、灯具、高光不能仅凭亮度比例淘汰 |
| 重复动作 | 往返运镜、重复展示等，优先保留最稳定且有信息量的一段，不把相似产品不同机位自动当重复文件 |

只有不存在满足用途的有效片段，才按质量归“不可用”。倾斜构图、低纹理、重复格栅干扰、速度或抖动拿不准时，保留“备用/待复核”，不混入精选。

人物宣传素材另检查主体脸部清晰、曝光、表情、遮挡、闭眼、人物截断及正式程度。不能通过推断人物身份或生成修脸来代替筛选；人物筛选仅在对应用途时启用。

### 4. 每条独立检查开头和结尾

- **开头稳定点start**：去掉试拍、调整机位、起始明显晃动；从稳定且有意图的运镜开始保留。
- **结尾结束点end**：在有效运镜完成后，明显晃动、撤机、失焦或方向失控开始前结束。
- **同一条必须检查两端，允许同时去头去尾。** 开头本来稳定可以保留0秒，结尾本来有效可以保留原终点；不为了“每条都裁”强行剪掉好内容。
- 每条满足`0 <= start < end <= 原片时长`。首版默认只保留一个连续区间；中间有坏段时选最好的一段，不擅自拼接多个分散片段。
- 复用用户示例里的判断逻辑，不复制秒数。例如一条尾部在3.5–4秒出现结束晃动，另一条开头约1秒才稳定，不代表其他素材都去头1秒或截止3.5秒。
- 用原片时间轴保存切点。从旧导出分析时，回溯原始区间；未变速时原片时间为旧start加成品时间，有变速或拼接时须使用完整映射。没有映射就列待复核，不猜测。
- 密集查看切点附近，并在能播放时按原速确认。用户明确指定的起止点可直接执行，注明用户依据；模糊的示例范围仍须核对。
- 不自动变速、稳像、补帧、调色、裁画幅或降噪。需要修复时另列建议，获得授权后单独处理，不靠减速掩盖糊片。

### 5. 分类、标签和命名

- 状态：待筛选、可用、备用、不采用；复核程度：待复核、抽样初筛、播放复核。记录质量问题、理由、start/end、分类、景别、场景、标签及备注。
- 分类可自定义，按项目用途归档。例如柜体与五金、墙板与格栅、纹理细节、茶几与组合、沙发展示、展厅空镜、工艺过程、人物口播、活动记录、其他。
- 名称固定为`YYYYMMDD-景别-场景名称.mp4`，例如`20261007-大特写-纹理展示.mp4`。
- 景别单选：大特写、近景、中景、全景、大远景。场景支持补充：纹理展示、衣柜展示、空镜、厂房、成品衣柜、木材、餐桌、沙发、茶几、门等。“/”表示或者，不写入文件名。
- 日期优先沿用用户指定/项目已有日期，未指定默认整理当天并说明，不将整理日期冒充拍摄日期。景别或场景拿不准时保存建议，不编造。
- 同名追加`-002`、`-003`等，处理Windows非法字符与保留名。命名作用于输出副本，不重命名原片。
- 批量规则默认保留逐条人工微调；用户明确要求全量重新审核时才重新定点，保留旧记录和可回溯理由，检查版本冲突。

### 6. 导出与验收

- 先预览目标目录、名称、保留区间、时长、处理方式及错误；已获授权的批量导出可执行，不反复确认同一机械步骤。
- 输出使用独立批次目录，成品按日期/分类归档；备用与不可用单独放置、不混入精选。复核原片副本必须明确注明“未裁切”。
- 有裁剪默认从原片精确重编码为H.264＋AAC MP4，非关键帧粗略流复制不可冒充精确裁剪。音轨不存在不强制添加。
- 未裁剪、仅分类改名且格式兼容时直接复制；需要转换才转码。保留原画幅、方向和帧率/时间戳语义，不承诺重编码无损。
- HDR处理链未验证时暂停该素材导出，避免静默颜色异常；可变帧率按原时间戳处理并核验同步，不强行套固定帧率。多音轨或特殊色彩需求先明确保留策略。
- 默认单个处理任务，编码及滤镜线程适度限制（通常1–2）；避免并发吃满用户电脑。允许取消、重试和断点恢复，不无限重试失败素材。
- 永不覆盖已有结果。未完成文件明确标记，不计入成品；清理任何文件都需单独审核。重新导出放新批次，不删除上轮文件。
- 批次根目录保留一份总索引，包含原路径、输出路径、状态、分类、景别、场景、start/end、时长和理由。**每个成品旁、分类文件夹内不放逐条索引。** 如需全量待复核清单只在批次根目录提供。
- 验证实际文件数量、目标名、时长误差、画幅方向、音轨存在性、完整解码、裁切边界及原片未改变。已知恒定帧率的受控测试检查裁切误差不超过一帧；技术未验证时不宣称达到此精度。
- 原片保护使用处理前后文件特征，必要时哈希对比。技术验收不等同画质、运动流畅性或音画同步的最终人工验收。

## 低Token与真实审核

1. 本地完成扫描、时长门槛、命名、复制、编码和校验；只读数量、分布、异常和待处理摘要，不把全部日志塞入对话。
2. 每批最多10条；首轮每条最多6张带时间点缩略图。长片明确标记抽样预览。
3. 复用文件特征、分析方法版本和缓存。素材不变不重复抽帧；规则改变重新做决策，不能盲用旧规则的结论。
4. 只对疑似边界或画质问题加密抽帧，必要时看高清；普通画面分类不默认音频转写，口播内容筛选才按需分析声音。
5. 边缘、亮度、帧差和运动估计只提示风险。相位相关/光流会受缩放、旋转、低纹理、格栅等干扰，不能把单个阈值当自动淘汰依据。
6. 静态抽帧不能证明原速运动稳定、整段清晰或边界逐帧正确。只做抽帧和运动趋势分析时标“抽样初筛”；实际连续播放复核后才能标“播放复核”。无法充分观察时降低结论强度、保留待复核。
7. 内容建议与确认结果分开保存；不确定的不要静默转为已确认。使用已有明确授权，但不扩大为删除、上传、发布或付费授权。
8. 全量筛选时比对实际扫描清单与审核清单，确保每条都有处理结果。重复调用复用已验证输出；文件或参数变化生成新结果。

## 调用与完成汇报

示例：使用本Skill整理指定文件夹，原片不足3秒列不可用，逐条查两端稳定点，只保留一段，按日期-景别-场景命名，裁切导出到指定目录，待复核单列，不改原片。

结束时说明扫描总数、裁切成品数、双端裁切数、备用/不可用/失败数、是否变速、实际输出位置、验证项目及仍未完成的人工复核。区分“规则已安装”“建议已保存”“文件已导出”“技术检查通过”和“业务验收通过”，不把其中一个冒充另一个。
