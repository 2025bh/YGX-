# 本地报价审核平台制作要求

## 主流程

导入并冻结AI原稿 → 导入指定人工对照 → 按图号、部件及侧别配对 → 查看原图 → 修改数据与解释 → 保存证据和下一项 → 沉淀项目案例/规则候选。

比较保留AI原稿、人工对照、本次采用值三份。相同尺寸不是配对依据；重名、一对多或组合项目不能任意匹配。无法唯一配对的候选由人确认。修改人工答案也要留原始快照。

## 界面

项目首页搜索和C/B、审核状态筛选；工作台支持全部、差异、尺寸、计价、材料、价格、疑似漏项、多项、高风险、未处理。电脑并排图纸和数据，平板/手机切换图纸、对比、纠错；手机按字段卡片查看，不将宽表缩小硬塞。

浅灰背景、圆角卡片、清晰导航、蓝色主要按钮和克制动效可作为默认风格；用户选定参考网站时先核实实际页面，再沿用其视觉语言。深浅主题不反转图纸原色。主要操作为“保存并下一项”。

提供未保存提醒、输入校验、保存反馈、失败保留输入、重试与键盘焦点。截图支持文件、粘贴、框选/箭头与说明；记录标记坐标并在历史中回放。

## 看图与CAD连接

高清预览优先同版DWG原生导出的矢量PDF，缩略图不冒充高清。字体、细小尺寸和视图对应关系须与CAD核实。

CAD助手适配明确版本，只接收受限的打开、定位和取图任务。源版本哈希、项目、图号、图框范围和对象句柄绑定；捕获任务还绑定报价行ID与版本，切换部件不能把截图挂错对象。使用只读副本，检查模型空间、视图方向及修改状态，不强制保存、关闭老师傅其他文件。

## 数据与发布

单主机数据库，多电脑经登录接口访问；不把SQLite放共享盘供客户端直接写。可用React/TypeScript、FastAPI、SQLite和PDF.js；已有兼容系统则沿用。

纠错事务保存改前/改后、证据、理由与审核状态；保存请求用幂等键和负载摘要，报价行用期望版本检查。导入、补漏也要防技术重试重复计价。校验计价单位与计算模式，不让pending口径产生金额。

本地规则保存成功和主规则启用是不同状态。项目数值、项目单价、C/B方法和共用规范分别存储；通用规则须适用条件、排除条件、代码适配和案例验证。未实现的规则显式待适配。

备份数据库、资产、规则与版本快照。恢复到新目录，验证资产引用与哈希，不覆盖正在运行数据。部署先本机验证，再在目标电脑核实局域网HTTPS、账户、CAD版本与完整流程。

## 验收

测试单位、原值算量、缺值、缺价、人工展开、最低面积适用范围、C/B隔离、原稿冻结、重复提交、并发冲突、漏/多项与重新配对。实际操作导入、纠错、保存、刷新、证据回放、导出和备份恢复。

检查桌面和手机、深浅主题、窄窗口、200%缩放及长名称。平台能打开和技术测试通过不能代替老师傅完整业务验收。一键识别、销售权限、CAD真机和新规则执行未完成时如实列出。
