# 轻量多智能体协作

## 目标

用最少的窗口转发和上下文读取完成任务，同时保证生产操作不重复、状态可恢复、结果可验收。

不要把普通任务升级成多窗口项目。不要为了留下审计证据，把敏感原文和逐条成功结果重复输出到聊天。

## 先判断任务类型

收到请求后只分为四类：

1. **简单问答**：当前窗口直接回答，不建任务、不派单、不写账本。
2. **单业务域普通任务**：总控可先帮助分流；用户已在有权限且具备工具的业务窗口提出时，直接负责到底，不经过总控重复转发。
3. **单业务域高风险任务**：业务窗口执行，必要时创建一次性只读 Subagent 验收。
4. **跨业务域、复杂独立交付或对象冲突**：总控确定优先级、依赖、实际负责人和执行顺序；不代替业务窗口反复询问同一口径。

不确定是否正式采用的想法保持为候选想法，不自动创建任务或派单。

## 项目级总控与按需复盘

项目与窗口分开登记：项目有目标和交付物，窗口是执行者；同一窗口可以承担多个项目，但同时只保留一个执行焦点。通过稳定项目编号、任务编号与窗口标识恢复，不凭相似名称转移负责人。

总控优先给出当前优先事项及原因、依赖、阻塞、待用户决定事项和成果入口。普通任务由原执行窗口自行回读，只有风险或用户明确要求才独立验收；不为每个窗口安排自动验收。

在实质交付、阻塞、规则变化、切换或交接时更新最小任务状态。共用规则只维护正式来源，交接传目标、现状、决定、下一步、证据和已有授权引用；接收方先核对负责人和规则版本，不重新索要已明确的授权。

复盘频率由项目配置和用户选择决定。普通项目可以统一按周，只有用户指定的项目才按日；安装或升级本Skill不创建、启用任何自动化。不把此用户的某个固定时间写成其他项目的默认授权。

已有账本可选用随附Python脚本做确定性增量筛选、最小交接与脱敏共享；无需为此安装新的Agent框架。首次适配、脚本命令、复盘水位和共享格式见[增量总控接入](references/incremental-control.md)，仅在需要运行这些功能时读取。脚本不调用模型、业务API或其他窗口，不替代实际验收。

## 长期入口与执行任务

- 长期业务窗口保存领域规则与任务入口，不必承载所有复杂工作的完整聊天。
- 独立交付物需要多轮开发/试验，或要与另一任务并行时，建议单独执行任务；小任务仍在业务窗口做。仅当用户明确要求或确认新建时创建，不批量增加窗口。
- 一个执行窗口同一时间一个主焦点；切换前保存已完成、剩余、下一步与证据。用户说“继续”但有多个候选时，用简短名称确认，不猜，也不让用户复述历史。
- 复杂任务有独立恢复卡或等价任务段落；状态只保留一个事实源，其他卡片和索引由它生成或只保存引用。
- 总控负责优先级、需求拆分、依赖协调、阻塞处理与结果入口，复盘只是其中一项。总控当前运行时可跟进派发任务；未运行时不能宣称自动持续监控。
- 不因采用此方法就创建自动化。已有关闭、静默和通知偏好原样保留。

## 单一执行权

每个可写任务只能有一个执行负责人。任务开始前确定：

```text
task_id
owner_thread_id
execution_id
batch_key
locked_objects
```

- `owner_thread_id` 是唯一允许执行写入的窗口。
- `execution_id` 标识本次执行尝试；技术重试必须复用，不得创建第二次执行。
- `batch_key` 标识同一批业务输入；同一批次只能成功写入一次。
- 已有项目治理入口时，登记、编号、更新、对象锁和焦点切换必须走同一原子写入接口，使用任务版本防止覆盖。禁止各窗口手工追加共同账本；没有此接口的小项目不要假装已实现并发保护。
- 批次键由稳定业务对象、输入批次与明确版本决定，不因为日期、窗口或超时改变。请求文字不同但输入相同也要先查原批次。
- 其他窗口只能查看、催办或提供只读分析，不能因为用户等待、超时或负责人暂未回复而接管执行。
- 需要转交时，先明确撤销原负责人执行权，再把所有权转给新窗口；原窗口收到转交后立即停止。
- 转交前由原执行方停止写入并留下回执、检查点，再更新负责人；填入任意文本不等于实际停止。新执行方复核外部状态后续办。
- 任务编号相同不代表可以由多个窗口共同执行。对象锁必须同时约束任务、负责人和执行批次。

任何窗口发现已有负责人或已开始写入时，不得再次执行。

## 最少转发原则

- 用户在哪个具备权限的业务窗口发起单域任务，就由该窗口完成澄清、执行、回读和结果汇报。
- 业务域内部的人员口径、字段含义和结果确认，直接在原业务窗口询问用户，不转给总控代问。
- 总控帮助选择当前优先事项、协调跨任务依赖、处理冲突和重大异常，并维护结果入口；正常完成不再一律返回总控批准。
- 派单消息只传递完成任务所需的最小信息，不复制整段历史聊天。
- 如果接收窗口可以通过任务文件或来源引用取得输入，不在消息中再次粘贴敏感原文。
- 不为问题、整理、执行、验收分别建立永久窗口；独立验收使用一次性 Subagent。

## 何时使用 Subagent

普通新增、普通文档修改和可确定性回读由负责窗口自行验证，不创建 Subagent。

以下情况才考虑一次性独立验收：

- 删除、批量更新或不可逆操作。
- 修改生产字段、公式、权限、工作流或部署配置。
- 对外发送、金额、工资、报价、安全或隐私相关操作。
- 用户明确要求独立验收。
- 失败影响大，且只读复核能显著降低风险。

验收 Subagent 默认只读，不得顺手修改自己正在验收的成果。输出只包含结论、失败项、证据和是否允许推进状态。

## 幂等与超时处理

- 写入前查询同一 `batch_key` 或业务幂等键是否已经开始或完成。
- 部分成功时停止，按已返回的记录 ID 和业务键清点，不整批重跑。
- 命令超时或窗口无响应时，先查询真实外部状态；确认没有产生结果后才能复用原 `execution_id` 重试。
- “用户正在等待”不是接管任务或重新执行的理由。
- 重复业务数据按业务规则处理；技术重复执行必须阻止。不要把“业务允许重复记录”误用为“同一批任务可以重复写入”。

## 状态与同步

只在关键节点更新共享账本或外部总控台：

```text
任务创建
实质交付或本地验证完成
发生阻塞或冲突
任务切换或交接
业务验收通过
任务停用
```

普通的内部思考、开始读取、完成一半和等待短时工具结果不需要跨窗口同步。

- 项目已有任务账本时沿用其状态枚举和安全边界。
- 项目没有账本时，不为了简单任务强行建立复杂控制面。
- 外部总控台是人看界面时，机器事实主源仍以项目约定为准。
- 同步前检查任务编号唯一；发现本地或远端同号任务时停止同步并先去重。
- 同时检查状态枚举、实际负责人、批次与规范对象键；只有明确验收证据才能收口或释放锁。未知旧状态标注待核实，不据日期推断完成。
- 规范对象键必须复用；自然语言近义词、路径别名和两台电脑的副本不自动等价。普通本地锁不提供跨机器分布式保证。
- 外部同步采用真实产物链接；没有链接就保留空值和结果文件入口，不把看板地址当成果地址。同步前核对人工改动，部分成功或响应不明先回读，不盲目重建。
- 本地协作脚本不等于操作系统权限隔离；直接调用业务工具仍可能绕开约定。必须由业务执行器同时落实幂等与回读，不承诺仅靠窗口规则就绝不重复。

## 低 Token 结果汇报

正常成功只汇报摘要：

```text
任务编号或批次：
请求数量：
成功：
失败：
回读：通过 / 有异常
异常项：无 / 简短列出
```

默认规则：

- 不逐条复述用户原始输入。
- 不在聊天中重复输出手机号、邮箱、地址、客户原文、内部对象 ID、消息 ID 或全部 `record_id`。
- 成功记录不逐条展开；详细证据写入项目约定的本地受控日志。
- 只展开失败项、字段不一致、重复执行风险和需要用户决定的异常。
- 用户明确要求查看逐条结果时，仍先脱敏；只有业务确实需要时才展示必要字段。
- 不在每次正常完成时重复输出“总账条数一致、远端多余为零、锁冲突为零”等内部健康指标；仅异常或用户要求时展示。
- 定时复盘先用脚本比较任务实质字段与规则指纹，再查看有变化窗口的最新摘要；列表更新时间只是线索，检索摘要可能是旧开场，不能作为当前成果证据。
- 设定输入预算，超出部分保留待查；没有变化保持静默，不把旧任务每周重讲。准备摘要不等于已复盘，确认完成后才推进水位，失败或超时不得提前确认。
- 共享同事项目时使用来源与项目编号区分，先预览脱敏包。远端摘要不覆盖本地任务、不赋予访问对方机器或接管执行的权限；具体传输须沿用用户的实际授权。

## 上下文恢复

窗口恢复时只读取：

1. 项目协作规则。
2. 项目当前状态。
3. 自己负责的当前任务。
4. 对应业务正式文件。
5. 最近一条相关执行或验收证据。

不要默认读取完整历史聊天、全部任务账本或其他业务域文件。恢复后先确认自己是否仍是唯一负责人，再继续写入。

项目人员名单、价格、表标识、目录和生产操作规则留在项目适配层，不写进本通用 Skill。换公司复用协作方法，重新配置业务事实和权限。

## 重复执行事故

发现同一批次被重复执行时：

1. 立即停止所有继续写入。
2. 将任务标记为阻塞并保持对象锁。
3. 只读核对两次执行的时间、负责人、数量和结果范围。
4. 不自动删除、更新或合并生产结果。
5. 给用户一个简短事实说明和最小修复方案；涉及删除必须取得明确批准。
6. 记录事故原因，补充负责人租约、批次幂等或同步唯一性检查后再恢复任务。

## 完成标准

一个任务完成时应满足：

- 只有一个窗口执行过写入。
- 结果已按任务要求回读。
- 异常和残余风险已说明。
- 详细证据已落受控位置，聊天只保留摘要。
- 高风险任务完成了必要的独立验收。
- 对象锁在业务完成后释放。

不要把上传成功、脚本运行成功、部署成功或消息接口返回成功直接写成业务验收通过。
