# 多窗口项目总控与增量复盘

版本：1.1.0。沿用`orchestrate-multi-agent-work`原名称升级。

适合把一个窗口作为总控、其他窗口按专业或项目执行的个人与小团队。总控处理优先级、依赖、阻塞和待决定事项，执行窗口负责实际交付与普通验证。

## 这次升级

- 项目和窗口分开归属，通过任务号与实际负责人恢复，减少重复解释。
- 最小交接摘要保留已完成、剩余、下一步、证据与原授权引用。
- 复盘先比较变化，限制每轮输入，完成后才确认水位；同周期重复唤醒不重复报告。
- 普通任务自行验证；每日复盘只覆盖用户指定项目，不默认逐窗自动验收。
- 同事进度包按来源隔离，默认隐藏路径、联系方式、凭据和业务链接，仅预览，不覆盖本地状态。

## 安装与升级

把下面这段发给自己的Agent：

```text
请从 https://github.com/2025bh/YGX-/tree/main/skills/orchestrate-multi-agent-work
安装完整目录。已有同名Skill时升级原目录，先保留我自己的定制规则。
先读README.md和SKILL.md，核对我的项目路径、现有任务状态源和窗口规则。
需要运行增量总控脚本时再读references/incremental-control.md。
不要复制发布者的任务、窗口ID、公司目录或自动化配置。
```

安装后可先说：`用这个Skill梳理我正在做的项目，告诉我谁负责、卡在哪里、下一步做什么。`

## 工具与范围

方法规则可直接使用。附带脚本需要Python 3.10及以上，不依赖付费API或第三方Python包；运行时明确指定自己的项目根目录。已有账本格式不同先适配，不覆盖现有AGENTS.md或任务文件。

Skill不自动创建窗口、不常驻后台、不自带定时执行或团队账号，不默认访问业务记录。复盘日程需要使用者明确选择，再通过所在应用支持的自动化工具创建。当前不包含可视化面板；面板可在实际需要时接入只读摘要。

完整接入步骤、命令和测试见[增量总控接入](references/incremental-control.md)。示例均为虚构数据；同事须使用自己的项目和权限。
